|---|---|---|
| GPU | NVIDIA RTX A500 Laptop, 4096 MiB, compute cap 8.6 (Ampere) | 1× NVIDIA H100 per node (80 GB), partition `gpu-h100`, account `p_scads_celltracking` |

| Inference capacity | Fits (10.7M-param transformer, ~43 MB f32; peak 0.7–2.6 GB) | fits trivially |

**Rule of thumb for this directory:**
- `cnn_ssl.py` (ScaledCNN NT-Xent pretraining) runs locally on the A500 — small CNN, ~1000 steps.
- `cnn_probe.py` and `probe/train_cnn_probe.py` run locally on the A500.
- CNN-injection **inference** from the 6 archived checkpoints runs on the A500, but the checkpoints' `train_config.yaml`/run dirs live on the cluster (they are 129–147 MB `.ckpt` files, see §5.7).
- CNN feature-injection **training** is H100-only: the configs point at HPC-absolute data paths and `cnn_checkpoint`, and the A500 OOMs at the configured batch size 48.
- DeepCell cross-dataset eval is cluster-only (DeepCell data is on-cluster; `traccuracy.CHOTAMetric` and the DeepCell data must be on the same machine).

## 4. Local (A500) experiments

### 4.1 ScaledCNN NT-Xent pretraining — `cnn_ssl.py`

Trains a `ScaledCNN` (128-dim embedding; `large` = channels `[32,64,128,256]`, 4 conv layers, ~200K params) with the NT-Xent (or BYOL) contrastive loss on 64×64 patches cropped at cell centroids from vanvliet frames, using two views generated by the distortion pipeline (affine → jitter → dropout).

**Exact CLI used for the shipped checkpoint:**

```bash
V=benchmark_ssl/.venv/bin/python
cd benchmark_ssl/cnn_encoder
$V cnn_ssl.py \
    --loss ntxent \
    --scale large \
    --steps 1000 \
    --distortion-strength strong \
    --max-frames 40 \
    --lr 0.001 \
    --outdir probe
```

Defaults that were left at their default values: `--data-dirs ../../data/vanvliet` (resolves to `research-proj/data/vanvliet`), `--conditions rpsM,recA,pheA,metA,cib,trpL`, `--seed 42`.

**Outputs:**
- `probe/cnn_ntxent_large.pt` (5.9 MB) — checkpoint dict with `model_state_dict`, `scale`, `out_dim` (128), `args`, `history`, `distortion_params`. **Exists locally.** This is the exact checkpoint injected by all CNN training configs.
- Note: `probe/cnn_byol_compare/cnn_byol_large.pt` and `probe/cnn_ntxent_compare/cnn_ntxent_large.pt` are comparison checkpoints from an earlier medium/large NT-Xent vs BYOL comparison.

**Status: DONE locally.** Runnable locally (scale=large, 1000 steps, distortion=strong); the A500 handles it easily (CNN-only training).

### 4.2 CNN probe — `cnn_probe.py`

Evaluates the frozen NT-Xent CNN vs a frozen random CNN on edge-prediction probes (linear + MLP) over consecutive frame pairs.

```bash
cd benchmark_ssl/cnn_encoder
$V cnn_probe.py --scale medium --checkpoint probe/cnn_ntxent.pt
```

**Result (verbatim from `probe/cnn_probe_results.txt`):** NT-Xent linear bal_acc **0.5000**, MLP bal_acc **0.5000**, F1 0.0000, acc 0.8331 — identical for the Random CNN. The 0.500 balanced accuracy means no edge signal was learned.

**Status: DONE locally.** This single-split probe is replaced by the unified 5-fold edge probe (`benchmark_ssl/probe/unified_edge_probe.py`, `cnn_frozen` feature = ScaledCNN-large + `cnn_ntxent_large.pt`), which reports CNN-NT-Xent MLP **0.7031 ± 0.0554** (report value 0.703). The `0.500` number must NOT be cited as the CNN feature quality; the unified probe is the source of truth.

### 4.3 `probe/train_cnn_probe.py` — TinyCNN end-to-end edge probe (located at `benchmark_ssl/probe/train_cnn_probe.py`)

Trains a TinyCNN (~3K params, 64-dim embedding) + linear `EdgeProbe` jointly with BCEWithLogitsLoss (pos_weight auto-computed) on same-cell vs different-cell edge prediction. Saves `probe/cnn_probe.pt`.

```bash
cd benchmark_ssl/probe
$V train_cnn_probe.py        # runs from benchmark_ssl/probe/; resolves data root automatically
```

This produces the `cnn_e2e` feature line (0.500, no signal) referenced in the edge-probe analysis. Runnable on A500.

### 4.4 CNN-injection INFERENCE from archived checkpoints — A500-runnable, but training is H100-only

- **Inference:** the 6 archived checkpoints (baseline + 5 CNN variants, see §5.7) are 129–147 MB Lightning `.ckpt` files; the underlying TrackingTransformer is 10.7M params (~43 MB f32). Loading and running inference (e.g., vanvliet eval via `eval_traccuracy/eval.py`) fits comfortably on the A500 (peak 0.7–2.6 GB).
- **Training:** H100-only. Reasons: (a) all `configs/vanvliet_*_cnn*.yaml`/`vanvliet_lambda_*.yaml` use HPC-absolute `input_train`/`input_val`/`cnn_checkpoint` paths; (b) the A500 OOMs at the configured batch size 48 (measured: B=48,N=500 OOM; B=8,N=2048 OOM). The binding memory constraint is the ~10 live `[B,N,N]` association/loss tensors in the training loop.

## 10. Early-stopping guidance

- All CNN/lambda runs used `--epochs 500` as an **upper bound only**. Lightning early stopping (patience **83**) already captures the converged optimum; several runs stopped far earlier than 500 (e.g., cnn_dropout_additive early-stopped at epoch 136, cnn_trainable at 91).
- **Do not re-run to 500 epochs when val_loss has plateaued.** Patience 83 stops near-optimal, and beyond the best epoch val_loss typically *rises* (e.g., cnn_trainable 0.036 → 0.083, cnn_dropout 0.016 → 0.021).
- For any future long run (e.g., multi-seed K-sweep), budget 48 h but expect 6.4–11 h of actual runtime per model (K-sweep clean runs early-stopped at epochs 237–406).

### 11.2 The post-LayerNorm injection trap

Injection point in `model.py` (~line 481):
```python
features = self.norm(features)           # LayerNorm applied FIRST
features = features + self.cnn_proj(cnn_out)   # CNN added AFTER norm (un-normalized residual)
```
Checkpoint forensics, identical across all four CNN variants (frozen/trainable × dropout/no-dropout):

| Metric | Value |
|---|---|
| `cnn_proj.weight` norm | **10.81** |
| `proj.weight` norm | 11.74 |
| Per-dim norm ratio cnn / proj | 1.0034 |
| Output dims near-zero (cnn_proj) | **0 / 320** |

The model never learns to turn down the CNN signal — SGD cannot cross the saddle barrier (it would need to increase loss first). λ(t) decay did not fix it.
