## 1. What the Proposal Asked

> *"Can we make transformer-based cell tracking more efficient by exploiting the sparsity of the spatial-cutoff attention pattern?"*

The proposal hypothesized:
1. Replace dense masked SDPA (O(N²)) with gather-based sparse attention (O(N·K·d))
2. Precompute KNN indices, gather K_sel/K_sel, run SDPA without mask → enables FlashAttention
3. Add token reordering for memory locality
4. Produce throughput/memory benchmark plots across N, K, L
5. Optionally port winning variant into Trackastra, verify training parity

## 2. What We Actually Found

| Proposal claim | Actual finding | Verdict |
|---|---|---|
| Gather enables FlashAttention | q_len=1 after reshape → FlashAttention refuses dispatch (or runs inefficiently). CuDNN explicitly rejects q_len=1. | **Wrong.** |
| Gather scales as O(N·K·d) | Gather copies scattered memory → O(N·K·d) reads with poor locality. Kernel launch overhead N × 10 µs dominates the "saved" compute. At N=256: gather approach = 994 µs vs masked dense = 193 µs. | **Wrong direction.** |
| Token reordering helps | SpatialReorder showed <3% throughput benefit after reorder/unreorder overhead. | **Correct (negative).** |
| Speedup over baseline | The 1.6× claim at N=2048 compares against original dense masked (cdist per layer). Against the correct cached-dist baseline (cdist once, shared across layers), no gain exists at dataset scale. | **Irrelevant at dataset N.** |
| Port into Trackastra | GatherSparseAttention ported. K=16 edge accuracy (0.998) > dense (0.977) — KNN acts as regularizer. But training throughput: indistinguishable from baseline (<2% difference at N ≈ 140). | **Regularizer, not speedup.** |

**What the proposal did NOT anticipate but we discovered:**
- The correct sparse approach is KNNMaskSparseAttention (scatter, not gather) — 3.1× faster than masked baseline at N=256 in benchmark
- Attention is **not the training bottleneck** at dataset N ≈ 140 (<5% of step time). Even a 10× attention speedup yields <5% total throughput improvement.
- F.scaled_dot_product_attention dispatch: any `attn_mask` arg forces EfficientAttention (not FlashAttention). The "mask tax" is a single 21 µs fixed cost — cheaper than any alternative encoding at N < 2000.
- Three independent approaches (KNN gather, KNN scatter, NSA) converge on the same conclusion: FlashAttention's single fused kernel with an N² mask beats all sparse orchestrations at N < 2000.
- FlexAttention with `score_mod` (PyTorch 2.5+) is the only escape from the mask dispatch penalty. Potential ceiling: 14-17 µs at N=256 vs. current best 33 µs (KNN scatter). Gap: 16 µs = 0.004% of a 400 ms training step.

## 3. Options

### Option A: Write up §4.1 as-is — RECOMMENDED

**Content:** Full investigation narrative covering all methods tested, profiler root-cause analysis, the mask indirection principle, and the honest conclusion that the gather hypothesis was wrong but the investigation produced a better method (KNN scatter) and identified the true bottleneck (mask dispatch, not N² compute).

**Remaining work:**
- Produce final benchmark plots (data exists, need matplotlib figures): ~4 hours
- Write §4.1 thesis chapter: ~1 day
- Include flex_attention as "Future Work" paragraph (no implementation)

**Strengths:**
- Honest scientific narrative — hypothesis tested, found wrong, root cause identified, alternative proposed
- Multiple methods tested (7 variants + NSA from literature)
- Profiler-backed analysis (not just benchmarks)
- Genuine insight: mask indirection principle
- The KNN-as-regularizer finding (edge accuracy 0.998 vs 0.977) is a positive result

**Weaknesses:**
- "Negative result" chapter — gather approach didn't work
- No measured flex_attention data point (only theoretical ceiling)
- The KNN scatter method exists but was never the proposal's approach

**Risk:** Low. Chapter is substantial and well-evidenced.

### Option B: Implement flex_attention + write up — STRETCH

**Additional work beyond Option A:**
- Implement FlexAttentionSpatial in model_parts.py: ~2 hours
- Benchmark against KNNMask at N = 128-8192: ~2 hours (GPU time)
- Measure compilation overhead: ~30 min
- Integrate findings into writeup: ~2 hours
- Total: ~1-2 days

**Gain over Option A:**
- Closes the "what if" question definitively
- Shows awareness of cutting-edge PyTorch features
- One additional data point in an already-dense chapter

**Cost:**
- 1-2 days of a ~14-day remaining window
- flex_attention is PyTorch 2.5+ only — cannot be ported to training cluster (PyTorch 2.3)
- At dataset scale: 16 µs improvement is not measurable

**Risk:** Medium. Implementation straightforward but compilation issues possible. Benefit marginal.

**Verdict:** Nice to have. NOT essential. Only if time permits after §4.2 is on solid ground.

### Option D: Abandon §4.1, full §4.2 focus — NOT RECOMMENDED

**Content:** Drop §4.1 from thesis, write only §4.2 + §4.3 + evaluation.

**Why not:**

- The mask indirection analysis is intellectually coherent

## 4. Recommendation

**Primary path: Option C (minimize §4.1 writeup, pivot to §4.2).**

Rationale:
1. §4.1 is research-complete. The remaining work is documentation, not discovery. A compact but thorough chapter (3-4 pages + figures) is appropriate for a negative-result contribution.
2. §4.2 is the domain's novel contribution. The proposal's core question ("can SSL pretraining reduce annotation needs for cell tracking?") is genuinely unexplored. The current implementation is architecturally wrong — fixing it is higher-impact than polishing §4.1.
3. Time is finite (~14 weeks total, ~4-6 weeks remaining). A strong §4.2 with any result (positive or negative) + a complete §4.1 is better than a polished §4.1 with no §4.2.

**Fallback: Option A.** If §4.2 produces negative results quickly (e.g., identity BCE fails to converge), pivot back to documenting §4.1 thoroughly with flex_attention benchmark (Option B) to strengthen the thesis.
